## Git
- Never run `git commit`, `git push`, `git rebase`, `git merge`, or `git reset` on your own.
  I make all commits myself.
- Only do these if I explicitly ask for that git task in my current message.
- Read-only git commands (status, diff, log, show, blame) are fine.
- When you finish a change, stop and let me review and commit it.

## Code Style
- Prefer clear function and variable names over comments. If code needs a comment to
  explain *what* it does, rename or restructure it first.
- Use comments for the *why*: non-obvious decisions, workarounds, external constraints,
  and anything that would surprise a reader.
- Don't add comments that restate the code, and don't leave comments about your changes
  (e.g. "updated this", "new helper").
- Leave existing comments alone unless they're now wrong or I ask you to change them.
